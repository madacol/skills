# Patterns

Use when the user wants reusable ideas.

| Pattern | Best for | Output |
|---|---|---|
| Workspace operator | Projects with files, decisions, tasks, and status. | Living project folder: index, owners, next actions, risks. |
| Batch worker | Many similar files, rows, screenshots, receipts, or messages. | Processed batch, counts, exceptions, packaged result. |
| Evidence reconciler | Sources that should agree but may conflict. | Mismatch report with links/rows/files as proof. |
| Browser clerk | Portals, forms, bookings, vendor onboarding, downloads. | Prepared browser workflow and handoff point. |
| Review board | Decisions needing independent lenses. | Merged review: risks, disagreements, recommendation. |
| Runbook executor | Known procedure with steps and gates. | Step log, evidence, blocked points, approval requests. |
| SOP distiller | Work that happens repeatedly but lives in someone’s head. | Checklist, operating manual, templates, trigger rules. |
| Launch room | Events, releases, campaigns, submissions. | Go/no-go packet, owner list, risk list, final checklist. |
| Change monitor | Portals, repos, vendors, trackers, policies. | Only meaningful changes, with source evidence. |
| Simulator | Interviews, negotiations, incident drills, tutoring. | Practice run, score, weak spots, next drill. |
